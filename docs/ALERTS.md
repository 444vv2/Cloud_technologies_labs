# Сповіщення

Усі алярми CloudWatch (`infra/monitoring.tf`) надсилають листи через одну SNS-тему `alerts` на `alert_email`. Кожен має `alarm_actions` (лист при переході в ALARM) і `ok_actions` (лист при поверненні в OK), тобто на кожен інцидент приходять два листи.

## Перелік алертів

| Алярм             | Метрика                                                | Умова                         | Коли приходить лист про тривогу                                                         | Лист про норму         |
| ----------------- | ------------------------------------------------------ | ----------------------------- | --------------------------------------------------------------------------------------- | ---------------------- |
| `cpu-high`        | `AWS/ECS` `CPUUtilization` (Average)                   | > 70%, 2 з 2 періодів по 60 с | CPU сервісу вище 70% дві хвилини поспіль, найімовірніше під час сталого навантаження    | CPU знову ≤ 70%        |
| `target-5xx`      | `AWS/ApplicationELB` `HTTPCode_Target_5XX_Count` (Sum) | ≥ 1 за 60 с                   | додаток відповів хоча б одним кодом 5xx, наприклад через `GET /debug/error` або збій БД | за хвилину без 5xx     |
| `unhealthy-hosts` | `AWS/ApplicationELB` `UnHealthyHostCount` (Maximum)    | ≥ 1, 3 з 3 періодів по 60 с   | health check падає три хвилини поспіль                                                  | усі екземпляри здорові |

## Алерт навантаження

**Умова:** CPU сервісу > 70% протягом 2 хвилин. Під час тесту приходить лист про тривогу, а після спаду навантаження лист про норму.
