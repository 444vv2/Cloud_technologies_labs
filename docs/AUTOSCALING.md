# Автоматичне масштабування

## 1. Застосунок (ECS service `app`)

Ціль масштабування `aws_appautoscaling_target.app`: межі змінюються розкладом, а всередині меж кількість задач веде політика за CPU.

### Розклад день / ніч (Scheduled Actions)

Часовий пояс: `Europe/Kyiv`.

| Дія   | Cron (`schedule_*_cron`) | Час   | min | max |
| ----- | ------------------------ | ----- | --- | --- |
| day   | `cron(0 7 * * ? *)`      | 07:00 | 2   | 4   |
| night | `cron(0 23 * * ? *)`     | 23:00 | 1   | 4   |

- **Вдень (07:00–23:00)** мінімум 2 задачі: запас на випадок відмови однієї й менше затримок на старті навантаження.
- **Вночі (23:00–07:00)** мінімум 1 задача: економія, бо навантаження мале.
- Розклад змінює лише `min_capacity` і `max_capacity`. Якщо задач менше за новий мінімум (07:00), ECS одразу додає. Якщо більше за новий мінімум (23:00), задачі прибирає політика CPU, коли навантаження низьке (після `scale_in_cooldown`).

### Політика за CPU (Target Tracking)

| Параметр           | Значення                          |
| ------------------ | --------------------------------- |
| Метрика            | `ECSServiceAverageCPUUtilization` |
| Ціль               | 65% (`autoscaling_cpu_target`)    |
| scale_out_cooldown | 60 с                              |
| scale_in_cooldown  | 300 с                             |
| max                | 4 (`autoscaling_max`)             |

## 2. Воркер черги (ECS service `worker`, `ASYNC_WRITES=true`)

`POST /songs` повертає `202` і кладе повідомлення в SQS, а воркер записує пісню в базу.

| Параметр  | Значення                                                                      |
| --------- | ----------------------------------------------------------------------------- |
| min / max | 2 / 4 (`worker_min`, `worker_max`)                                            |
| Метрика   | backlog на задачу = `ApproximateNumberOfMessagesVisible` / `RunningTaskCount` |
| Ціль      | 10 повідомлень на задачу (`worker_backlog_target`)                            |
| Cooldown  | out 60 с / in 300 с (ті самі, що й у застосунку)                              |

Розкладу для воркера немає: він завжди тримає щонайменше 2 задачі. Якщо черга росте швидше, ніж воркери встигають її розбирати, додаються нові (до 4). Коли черга порожня, їх кількість повертається до 2.

## Підсумок

| Час / стан                              | Застосунок | Воркер |
| --------------------------------------- | ---------- | ------ |
| Ніч (23:00–07:00), низьке навантаження  | 1          | 2      |
| День (07:00–23:00), низьке навантаження | 2          | 2      |
| Високий CPU (>65%)                      | до 4       | —      |
| Велика черга (>10 на задачу)            | —          | до 4   |
