# Автоматичне масштабування

Файл: `infra/autoscaling.tf` (ECS Service Auto Scaling, Target Tracking).

| Параметр           | Значення                          | 
| ------------------ | --------------------------------- |
| min / max          | 1 / 3                             |
| Метрика            | `ECSServiceAverageCPUUtilization` |
| Ціль               | 60%                               |
| scale_out_cooldown | 60 с                              | 
| scale_in_cooldown  | 300 с                             |

## Cooldown

Період стабілізації — мінімальний час між двома діями масштабування в одному напрямку. Нові екземпляри ще стартують і не впливають на метрику; без паузи політика бачила б «все ще високий CPU» і додавала б зайве.
При cooldown = 0 система «смикається» (flapping): додає й одразу видаляє екземпляри, а видалення під навантаженням обриває запити й викликає нове зростання CPU.

## Чому зменшення повільне

AWS створює алярм зменшення, який вимагає 15 хвилин поспіль CPU нижче ~54% (90% від цілі), потім діє ще scale_in_cooldown 5 хв. Разом ≈ 20 хв після спаду.
